## 1. Что это

`aiProjectDashboard` — **личный ops-дашборд портфеля pet-проектов** на
**Kotlin/Ktor**. Одно место, где соло-разработчик видит состояние всех своих
репозиториев сразу:

- **CI-статус** каждого проекта (через GitHub Actions API);
- **последний коммит** и число **открытых PR**;
- **кросс-репо агрегатор TODO/FIXME/HACK** — сканирует локальные рабочие копии
  всех репозиториев на диске, собирает маркер-комментарии в один
  **AI-приоритизированный** список.

Это не SaaS и не сервис для других людей. Аудитория — один человек (автор).
Запускается **по требованию локально**, отдаёт веб-страницу на `127.0.0.1`
(и умеет работать headless через CLI-режим).

## 2. Зачем (и почему именно так)

- **Учебная цель — «другая мышца» Kotlin.** В портфеле уже есть Kotlin-проект
  `orm-nplus1-radar` — это IntelliJ Platform плагин. Здесь сознательно берётся
  **чистый бэкенд на Ktor**: HTTP-сервер, корутины, HTTP-клиент к внешнему API,
  сериализация, работа с процессами и файловой системой. Ни строчки IDE-плагинной
  специфики.
- **Реальная польза автору.** У портфеля ~9 репозиториев; проверять CI и
  «что я там недоделал» по каждому вручную — трение. Дашборд убирает это трение.
- **Дешёвая инфраструктура.** Осознанно выбран **локальный запуск без VPS** —
  расходы $0/мес (обоснование см. `TECHNICAL_PLAN.md §2`). Бюджет портфеля
  ($500 / $50–70 мес) остаётся нетронутым.
- **Приватность и безопасность по умолчанию.** Сервер слушает только loopback.
  Токен GitHub не хранится приложением — переиспользуется существующая сессия
  `gh auth` (см. `SKILL.md`).

## 3. Для кого

- Прежде всего — **сам автор** (dogfooding: дашборд агрегирует в том числе
  собственный репозиторий).
- Список агрегируемых репозиториев **настраиваемый** (JSON-конфиг), не
  зашит в код. Значит, инструмент переносим на любой другой портфель под
  `github.com/<owner>/*` с локальными копиями на диске.

## 4. Ключевые принципы

- **Нулевая инфраструктура** — никакого сервера, БД или хостинга ключей.
- **Настраиваемость, не хардкод** — портфель, маркеры, расширения файлов,
  порт — всё в конфиге; есть встроенный default-портфель для запуска «из коробки».
- **Graceful degradation** — сбой запроса к GitHub по одному репозиторию не
  роняет всю страницу: этот репозиторий показывается в degraded-состоянии.
- **Offline-режим для AI-ранжирования** — без LLM-ключа работает
  детерминированный эвристический ранкер (портфельная конвенция offline-mode).
- **Порты и адаптеры** — `GitHubClient` и `TodoRanker` — интерфейсы; реализации
  подменяемы, тесты используют детерминированные фейки/temp-директории.

## 5. MVP — две фазы

**Фаза 1 — агрегация статуса портфеля.** По списку репозиториев из конфига
собрать CI-статус, последний коммит, число открытых PR. Показать в веб-таблице
и/или в терминале (`--cli status`). Запросы к репозиториям идут конкурентно
(корутины); после post-MVP §2 весь портфель забирается одним GraphQL-батчем,
а CI берётся из check suites HEAD-коммита дефолтной ветки.

**Фаза 2 — кросс-репо TODO/FIXME-агрегатор.** Пройти локальные рабочие копии,
просканировать `.kt/.go/.ts/.tsx/.py/.php`-файлы, собрать комментарии-маркеры
(`TODO/FIXME/HACK/XXX`), **AI ранжирует** по важности/актуальности. Показать в
веб-вкладке и/или в терминале (`--cli todos`).

## 6. Что осознанно НЕ входит в MVP

Вынесено в [`POST_MVP_PLAN.md`](./POST_MVP_PLAN.md): постоянный сервис на VPS,
push-уведомления о падении CI, health-чеки внешних сервисов проектов,
GraphQL-батчинг, кэш/история статусов, реальный LLM-ранкер вместо эвристики,
аутентификация (не нужна для loopback-инструмента).
